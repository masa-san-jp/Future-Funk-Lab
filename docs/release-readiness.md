## 修正済み P1: 再生準備中の停止が取り消される

対象: `src/app.js` の `startSequence` と `seq-stop` のハンドラー。

再生開始は音声生成とAudioContext初期化を非同期で待つ。その間の停止に対して開始要求を無効化する処理がないため、停止後に待機が完了すると再生を開始してしまう。

再現検証では初期化完了を250 ms遅延させ、再生クリック直後に停止をクリック。500 ms後に `playing: true`、表示「16/8拍子で再生中 · 120 BPM」となった。初期化の遅延をテストで制御し、競合する操作順序を再現している。

合格条件: 停止より前の開始要求は、音声処理・初期化が後から完了しても発音しない。停止・削除・素材置換などの操作との競合も同様に扱う。

## 修正済み P1: ループOFFでも後半の発音が先頭へ回り込む

対象: `src/audio.js` の `patternTrack`、`AudioEngine.start`。

ループON/OFFにかかわらず周期バッファへ余韻を折り返すため、単発再生でも存在しない前周の音が先頭で鳴る。

再現: 120 BPM、4/8、0.6秒の素材をステップ4のみに配置し、ループOFFで音声をレンダー。実装の50 msの開始余裕を含めて本来の最初の発音は0.8秒だが、0〜0.3秒のRMSは0.128937となった。本来この区間は無音である。

合格条件: 単発再生では最初の配置より前に鳴らない。余韻と停止時刻の扱いも単発再生の仕様に整合させる。ループONでは従来の境界同期を維持する。

## 配布物の確認

現在の `dist/verification/` に、実素材を使った検証用の音声と結果JSONが入っている。このディレクトリを含む `dist/` 全体を製品としてそのまま配布しない。`npm run release` は製品HTML・依存ライセンス・再ビルド用ソース・説明だけを許可リストで取り込む。検証用音声を含まない配布候補とSHA-256、ファイル単位のmanifestを作成し、アーカイブの内容を検査する。ビルドと全テストが失敗した場合は配布候補を生成しない。`npm run site` は許可リストからローカルに配信用ファイルを生成するが、一般公開は行わない。Pagesの再開には所有者の明示的な承認が必要。
