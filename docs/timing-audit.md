# ループとシーケンサーの時間軸の検証

2026-10-18。ユーザー報告「シーケンサーがループと合わない」に対する検証と修正。

## 検証で不足していた点

従来は発音予約時刻、変換後の総フレーム数、定常音の周波数を検証していた。これらが正しくても、タイムストレッチが素材内のドラムのアタックを移動・欠落させれば、実際の拍は一致しない。音声の中身を検証していなかった。

## 再現結果と修正

- 44.1 kHz、8秒、120 BPM相当の16アタックを使用。最初のアタックは0.137秒。
- 従来のSoundTouchJS自動シーケンス設定では、1.5倍速で16アタックのうち5つを所定時刻付近で検出できなかった。0.5倍速では最大約69 msの位置ずれを確認した。
- 総時間を合わせるだけでは不十分なため、元音声のアタックを検出し、そのフレーム位置を変換先へ写して処理区間を固定するよう変更した。アタック部は短区間のピッチ変換と本文へのクロスフェードで保持し、本文にSoundTouchJSを使う。左右は共通の時刻で処理する。
- 0.5／0.75／1.5／2倍速で、検証用16アタックの欠落なし、位置誤差1サンプル未満を確認する回帰テストを追加。
- WAV読み込み → 90から120 BPMへ変換 → 拍頭で範囲指定 → チョップ → 8/8パターンに配置 → WAV書き出しまでの実音についても、各アタックの位置を検証する。

## BPMとループ長の関係

現在のBPMは4分音符基準、1ステップは8分音符。120 BPMでは1ステップ0.25秒、8/8の1周は2秒。サンプルの長さは任意であり、この式に合わせて勝手に切り詰めない。

原曲BPMが推定値のまま誤っていると、原速で読み込めてもシーケンサーの拍は原音に合わない。そこで、選択範囲の実測長とユーザーが指定した拍数から原曲BPMを校正する操作を追加した。

`原曲BPM = 60 × 選択範囲の4分音符の数 ÷ 原音上の選択範囲の秒数`

現在の変換後秒数から元音源のBPMを直接計算する誤りを避け、元音源の長さと保持した範囲の相対位置を使う。グローバルBPM未変更なら原速を保ってBPM表示も追従し、変更済みなら指定された目標BPMを維持して素材を再変換する。BPM入力は小数3桁まで扱う。

シーケンサーには1ステップと1周の秒数を表示する。音源の推定BPM、選択範囲の拍数、配置したステップが合っているかを確認できるようにする。

## 検証範囲

この修正は検出したアタックの時刻を保持するもので、全楽曲の拍頭を完全に自動認識するものではない。拍頭の選択とループ内の拍数は音源に合わせて指定する。実際のテンポが変動する音源の全拍を固定グリッドへ矯正する機能は含まない。

関連テスト: `tests/core.test.mjs`、`tests/browser/sync.spec.js`。

## 周回処理の再修正

従来の検証では、発音予定時刻だけを確認し、画面遅延時に音が欠落する問題と再生・書き出しの境界処理の違いを見落としていた。周期バッファを事前に構成し、音声エンジンで繰り返す方式に変更。任意長サンプルの余韻は周回先頭へ折り返し、cutは次の発音までに制限する。書き出しも同じ周期構成を使う。BPM自動推定の正確さや任意の素材内部の拍位置を保証する変更ではない。

## 実素材での再確認（2026-10-18）

使用中のChrome画面を読み取り、元素材 ローカル検証用の実音源、95 BPM、範囲83.885〜90.689秒、16/8、トラック1のステップ1・5・9とトラック4のステップ13という状態を確認した。表示上の先頭チョップは1.808秒。画面はまだ「末尾5 msフェード」と表示する旧版だった。編集中の音源・境界・配置は変更していない。

同じローカル実音源の83.885秒から1.808秒分を取り、最新コードの音声エンジンでトラック1を再現した。44.1 kHzでチョップ試聴周期は1.808004535秒、4ステップの発音間隔は1.263151927秒、両者の差は0.544852608秒。選択範囲全体は6.804秒だが、16/8パターンは5.052630385秒となる。

独立に元PCMを発音位置へ加算した参照波形との最大誤差は0。実際にOfflineAudioContextで連続4周をレンダーした音声と周期波形の比較も最大誤差0だった。したがって最新エンジンの周回処理自体は正しく繰り返すが、使用中の配置がチョップ試聴と同じ周期になるわけではない。前回の修正をもって素材とのループ同期が解消したとはいえない。

任意長素材は正当であり、音の末尾と次の発音が重なること自体は不具合と断定しない。また、この比較は楽曲全体の正しいBPMや個々の音楽的な拍頭を確定するものではない。検出した未解決点は、チョップ試聴の周期とシーケンサー配置間隔を一致させる関係が実装で保証されていないこと。

再現: `FFL_VERIFY_SOURCE='<元素材のローカル絶対パス>' npm run test:browser -- tests/browser/real-source.spec.js`。テストは既知の不一致を検出するものであり、その成功は同期問題の解消を意味しない。実音源はリポジトリへ追加しない。

## 同期処理を実装した後の実素材検証

未解決だった素材長と配置間隔の関係を、トラック別の長さ同期として実装した。既定は「配置に同期」。原寸再生とステップ数の明示指定も可能。チョップ境界を動かして合わせる方式ではなく、再生用音声を音程維持のタイムストレッチで生成する。

同じ実音源・95 BPM・16/8・トラック1のステップ1/5/9とトラック4のステップ13をUI操作で再現した。先頭のチョップは元1.807981859秒、同期後の試聴は1.263151927秒。配置間隔1.263157596秒との差は0.000005669秒（0.25サンプル、1サンプル未満）。元のチョップ境界の相対位置は完全一致を確認した。

独立に同期済みPCMを発音位置へ加算した参照波形と再生用周期バッファの最大誤差0。実際の音声エンジンが使用する全トラックをEQ・マスター込みで連続6周レンダーし、定常周回間の最大誤差0。WAV書き出しとの最大差0.000029743（PCM16量子化の範囲）。

追加で、1.808秒の素材に4アタックを持つ音源を用い、全トラックの配置後に16個のアタックが95 BPMと120 BPMの各グリッドから10 ms以内に収まることを検証した。3/5/7ステップへの指定、原寸への復帰、再生中の配置変更、ピッチ変更、137 BPMへの変更も検証。

実素材テストは不一致を期待する旧テストから、UI上で同期後の試聴・再生・書き出しが一致することを要求する回帰テストへ置き換えた。関連: `tests/browser/real-source.spec.js`、`tests/browser/loop-sync.spec.js`。
