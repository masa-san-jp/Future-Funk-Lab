# 初版の実装仕様

元資料: [2026-10-18 設計資料](20261018-future-funk-lab-sampling-spec-draft.md)。ユーザーによる「8＝8/8、16＝16/8、32＝32/8」の定義を反映したローカルWebアプリ。以下は、未決事項を実装可能にするための初版の判断であり、ユーザー承認済みの決定と区別する。

## 拍子・発音

- シーケンサーは各トラックの周期バッファを先に構成し、音声クロックの同じ開始時刻から再生する。画面用タイマーの遅延で音は欠落しない。
- 1ステップは8分音符（初期値）または16分音符。8分の4、8、16、32ステップはそれぞれ4/8、8/8、16/8、32/8拍子。16分は8、16、32、64ステップ。2026-10-28に16分を追加した（下記）。
- BPMは4分音符基準。8分の1ステップは `30 / BPM` 秒、16分は `15 / BPM` 秒。1周は `16分の数 × 15 / BPM` 秒。
- サンプルの長さは任意。「重ねる」で各音を末尾まで再生。「切る」は次の発音までで前の音を切り、直前5 msをフェードする。同じトラックのシーケンサー音だけが対象で、試聴音は独立。
- ループ再生では前周の余韻を保持する。ループオフは前周の音を含まない単発音声として再生し、最後の音は素材末尾まで鳴らす。再生位置の表示は1周で終了する。停止操作では余韻・試聴を停止する。
- 再生中に再生ボタンを押すと一時停止し、再開時は保持した周期内の位置から再生する。停止・先頭へ戻るでは位置を0にする。
- 書き出しは厳密に1周。再生と共通の周期バッファを使い、周回をまたぐ音は先頭に折り返して重ねる。ループON時は全体末尾のフェードを行わず、EQは先行2周で状態を整えてから1周を書き出す。ループOFF時は前周を含まない先頭からの1周を出力し、出力端を5 msフェードする。

## 素材・BPM・更新

| 操作 | 音源・境界 | ステップ／トラック設定 |
|---|---|---|
| ファイル読込・録音確定 | 素材を置換、範囲を全体に戻し、チョップを解除 | 初期化 |
| 元素材削除 | 原音、録音、変換後音源、チョップを破棄 | 初期化 |
| グローバル／元素材BPM変更 | 原音から変換し直す。範囲・境界は原音内の相対位置を保持して秒数に再変換。分離音源・トラック素材も再生成 | 保持 |
| 範囲再確定 | 新範囲を等分割、分割位置の微調整は解除 | 保持 |
| 分割数変更 | 確定範囲を等分割、微調整は解除。余ったトラックは空き | 保持。空きトラックは発音せず、分割数を戻すと設定が復元 |
| ステップ数変更 | 再生を停止して先頭へ戻す | 非表示ステップも保持し、ステップ数を戻すと復元 |

- 新しいファイル・録音・デモを読み込むと、グローバルBPMを解析した原曲BPMに揃え、テンポ比1で開始する。以前の素材の目標BPMは引き継がない。
- 原曲BPMの推定値を手動修正した場合も、グローバルBPMを明示的に変更するまでは目標BPMを追従させ、原速を維持する。グローバルBPMを変更した後は、原曲BPMを修正しても目標BPMを保持する。
- 元素材BPMの推定誤差は、選択範囲の拍数（4分音符単位）を指定して「この範囲からBPMを合わせる」で補正できる。元音源上の秒数から算出し、変更済みの目標BPMは保持する。
- タイムストレッチは検出したアタックを変換後の所定フレームに固定して処理し、素材内の拍を失わないようにする。修正根拠と検証範囲は [時間軸の検証](timing-audit.md) に記載。
- 原音を常に保持し、繰り返しストレッチした音を再ストレッチしない。
- BPM解析はエネルギー立ち上がりの自己相関による推定。60〜200 BPMを解析し、手動入力は30〜300 BPMを受け付ける。推定の倍／半テンポや非定常テンポは手動で補正する。
- 原音と変換後音源の長さは各10分まで。モノ素材はL/R複製、2ch以上は先頭2chを使用。内部処理は44.1 kHz。
- WAV・AIFF・MP3・AAC(M4A)・FLAC・Opus/Ogg・WebMを読み込む。AIFF以外はChromeの `decodeAudioData` で読む。読めない形式（ALACなど）は、書き出し直す形式を案内する。
- ChromeはAIFFを読めないため、`aiffToWav()` で同じビット深度・レートのWAVのバイト列に組み替えてから `decodeAudioData` に渡す。値は変換しないので、レート変換もWAVと同じ経路になる。対応するのは非圧縮AIFFと、AIFF-Cの `NONE`・`twos`・`sowt`・`fl32`・`raw `。それ以外の圧縮は形式名を出して止める。プロジェクトの照合（サイズとCRC32）は組み替える前の元のバイト列で行う。

## 範囲・チョップ

- 開始・終了は変換後音源の秒数。ズーム1〜100倍。波形本体はクリックでその位置から原曲を再生し、通常のドラッグで開始・終了の範囲を選択する。左右どちらの向きからも選択可能。拡大中の水平移動は「左右移動」ツール、Shift＋ドラッグ、横ホイール・縦ホイール・スクロールバーで行う。ツールの初期値は「範囲選択」。境界線全体または三角のドラッグと秒数入力でも範囲を微調整できる。
- 拡大してマーカーが画面外でも、「始点を指定」「終点を指定」を選んで波形をクリックすると、クリックした絶対時刻をその端点に設定する。右クリックメニューからも同じ指定が可能。通常は反対側の端点を保持する。始点が既存の終点以降になる場合は終点を曲末へ、終点が既存の始点以前になる場合は始点を曲頭へ戻し、1 ms以上の区間を保つ。ズーム・スクロール・確定済みチョップは変えず、端点指定操作では再生を開始しない。
- 原曲の再生位置とサンプリング範囲は独立。「原曲再生」は現在位置から曲末まで、「範囲試聴」は選択区間だけを再生し、「範囲ループ」は後者だけに適用する。範囲外でも原曲クリック再生が可能。
- 停止中も再生位置を保持し、原曲再生で再開する。ズーム時は画面内の再生位置を中心に拡大し、再生位置が画面外にあれば表示中央を維持する。パン操作は範囲・チョップ・再生位置に影響しない。
- 原曲波形にフォーカス中は左右キーで1秒、Shift併用で0.1秒シーク。Home／Endで曲の先頭／末尾から再生、Spaceで原曲再生／停止。
- 分割数は2〜8。初期値4。各区間を最低1 ms確保し、内部境界は交差させない。
- 両端の塗りつぶしマーカーは確定範囲の表示。移動するのは内部マーカー。範囲の再選択はサンプリング画面で行う。
- 吸着は初期オフ。刻みは選んでいるグリッド（8分／16分）、基準はサンプリングで選択した範囲の始点。実際の曲の拍頭を自動検出する機能ではない。
- 吸着オフでは矢印1 ms、Shift併用10 ms。吸着オンでは矢印1回でグリッド1つ移動。隣接境界との間にグリッドがなければ位置を維持する。
- 吸着をオンにすると内部の分割位置を選択範囲の始点からの8分音符グリッドへ揃える。範囲の両端は変えない。オンの間は範囲再確定・分割数変更時にも適用する。チョップ波形の縦線は同じ拍グリッドを表示する。
- チョップ試聴では音声クロックから再生位置を求め、波形上の再生線・再生区間の強調・区間内の経過時間・進行バーをフレームごとに更新する。区間末尾では先頭へ折り返し、切り替え・停止・削除時に表示も同期する。分割境界の微調整中も試聴を維持し、処理後に新しい区間へ音源と位置を更新する。
- 区間のループ試聴は同時に1つだけ。別の区間を押すと前の試聴を停止し、同じ区間を押すと停止する。シーケンサー開始時には試聴を停止し、自由走行の試聴ループとパターンが重ならないようにする。チョップ試聴は素の区間音、トラック試聴はピッチ・EQ・出力設定を反映する。

## ピッチ・EQ・レベル

- ピッチは±12半音＋±50セント（1セント刻み）。長さを維持する。
- ワーカーで変更対象の区間を処理し、鳴っている音は元の再生位置を保って差し替える。ピッチ変更中も再生を継続する。処理時間は素材長と端末性能に依存する。
- 信号順はピッチ → EQ → トラック出力 → マスター。
- EQは並列3バンドのクロスオーバー。6 dB/octは1次、12 dB/octはLinkwitz–Riley 2次、24 dB/octはLinkwitz–Riley 4次。LOW側に位相補償を入れ、全帯域0 dB時の振幅特性をフラットにする。
- 各バンドは0〜−∞、トラック出力・マスターは−∞〜+6 dB。スライダーの−60端点は−∞（ゲイン0）。EQ・出力・マスターの数値欄は空欄または `-∞` も受け付ける。
- Mを優先。複数Sはすべて発音。空きトラックのSは他の音を消さない。M/Sはトラック試聴にも適用する。
- マスターは全試聴とシーケンサーを通す。分離パートの書き出しはフィルター後の素材そのもの、シーケンサー書き出しはマスター設定を反映する。
- マスタートラックは画面下部に固定し、サンプリング・分離・チョップ・シーケンサーのどこを表示していても操作できる。表示幅で高さが変わった場合は下余白を調整して内容を隠さない。
- メーターはマスター後のL/Rサンプルピーク。dBFS最大値を保持し、0 dBFS超過でCLIP点灯。リセットボタンで保持値・クリップ表示を消す。自動リミッターやノーマライズは行わない。

## 音声分離・録音・書き出し

- `Mid = (L + R) / 2`。パートは同じMid素材から独立したHP／LP処理を行う。出力は同相信号の2ch。
- HPは50〜2000 Hz、LPは200〜8000 Hz。各勾配6／12／24 dB/octは1次IIR／2次Butterworth／2次Butterworthを2段で実装する。
- HPとLPのカットオフ逆転は許可する。結果は強く減衰するが無効な設定にはしない。
- 分離パートの波形はフィルター前のMid素材を表示し、再生はフィルター適用後。フィルター変更は再生中にも反映。再生中の書き出しは、その操作時のフィルター設定を固定して全体をレンダリングする。
- 録音はMediaRecorderで取り込み、停止後にPCMへ復号。保存ボタンで元の録音をWAV化する。保存先絶対パスはブラウザが公開しないため、ファイル名と保存要求の状態を表示する。
- 音声はネット送信しない。単一HTMLにDSPワーカーと依存ライブラリを同梱する。
- WAVはPCM16、MP3は192 kbps。ステレオ／モノ選択はシーケンサー出力に適用し、モノはL/Rの平均。分離パートは2ch出力。
- 元資料にないAI音声分離・調性補正は実装対象外。プロジェクト保存は2026-10-28に追加した（下記）。

## 検証

`npm test` はDSPの長さ・周波数、BPM推定、境界制約、WAV／MP3を検証する。`npm run test:browser` は実際のChrome上で取り込み、波形、チョップ、シーケンサー、BPM更新、EQ、分離、仮想マイク録音、書き出し、file URLでの起動を検証する。実マイクの音質と他ブラウザでの動作は未検証。

- 発音はJavaScriptタイマーから切り離し、トラックごとの周期バッファをAudioBufferSourceNodeでループする。全トラックを共通の開始時刻・同一フレーム数で再生する。画面用タイマーは再生位置表示のみを更新し、遅延時の発音スキップはない。

## 素材長と配置の同期（2026-10-18）

- 各トラックの長さモードは「配置に同期」（初期値）、「ステップ数を指定」、「原寸」。同期モードでは切り詰めや再生速度変更による音程変化を使わず、タイムストレッチで目標フレーム数へ変換する。
- 「配置に同期」は、そのトラックに複数の発音があれば周回を含む最短の発音間隔を素材1つの長さとする。単発配置なら他トラックを含む次の配置までの間隔。同時発音は同じ始点として扱い、間隔0にはしない。配置がなければ原寸。ミュート／ソロは長さに影響しない。
- 休符が長くても素材をそこまで引き延ばさず、同じトラック内では共通の素材長を使う。「ステップ数を指定」は0.25〜128ステップで長さを明示できる。「原寸」は任意長素材をそのまま重ねる／切る従来動作。
- 95 BPM、16/8でステップ1・5・9に配置したトラックは4ステップ分。元の素材が1.808秒でも、再生用は約1.263秒となる。サンプリング範囲・元音源・切り出し境界の秒数を変更しない。
- パターン1周を整数フレームに確定し、同期長も同じ周回フレーム数から計算する。発音位置との差は丸めの1サンプル以内。繰り返しは音声エンジンで行い、周回ごとの時間ずれを蓄積しない。
- チョップ試聴はピッチ／EQ前の同期済み音声、トラック試聴とシーケンサーと書き出しはピッチ処理後の同期済み音声を使う。ピッチ変更は同期長を保つ。
- 波形と境界は元の区間の時間軸に保ち、試聴カーソルは音声内の経過率を元区間上の位置へ写す。表示に元の秒数と同期後のステップ数・秒数を併記する。
- 配置・ステップ数・同期指定の変更では対象の音声を再生成する。再生・試聴・書き出しを開始する前に生成完了を待つ。再生中の変更は同じ周回時計を維持して対象トラックのみ更新する。

## 停止と非同期処理

- 再生開始要求は音声生成・AudioContext初期化の完了後も、要求番号、停止回数、素材の世代を確認する。停止・素材削除・素材置換・BPM変更より前の開始要求は、後から完了しても発音しない。
- 準備中の再生ボタンの再クリックは準備を取り消す。全停止はチョップ・原曲・トラック・分離パートの準備中の再生も取り消す。
- 内部境界の調整は遅延再生成を待ってから再生・書き出しを開始する。直後の書き出しでも古い音声バッファを使用しない。
- ループON/OFFの切り替えでは、現在の周回内位置を保って周期音声と単発音声を作り直す。単発音声に前周の余韻を折り返さない。
- チョップ試聴の波形座標は、音声を切り出した整数サンプル位置を基準にする。小数計算誤差でカーソルが区間の外側へ出ないようにする。

## プロジェクト保存（2026-10-28、#2）

- プロジェクトは設定だけのJSON（`schemaVersion: 3`）。ファイル名は取り込んだ曲の名前の拡張子を `.json` に変えたもの。元の曲は入れない。最初は元の曲を32-bit float WAVで入れる `.fflab` 形式だったが、4分で約85 MBになり、保存のたびに変換で画面が止まるため、同じ日に置き換えた。`.fflab` には対応しない。
- `source.kind` は `file`（取り込んだ曲）・`recording`（マイク録音）・`demo`。`file` と `recording` は、元の曲ファイルのバイト数とCRC32を持つ。録音はブラウザの中にしかないため、保存時に録音のファイル（MediaRecorderの出力をそのまま。`.webm` など）も一緒にダウンロードする。デモはプログラムで作り直す。
- 開くときは `.json` と曲を一緒に選ぶか、`.json` だけを選んで画面内の案内から曲を選ぶ。曲はサイズとCRC32で照合し、違えば案内を残して選び直させる。名前は照合に使わない。照合後、最初の読み込みと同じ `decodeAudioData` で読むので、同じブラウザなら元の音声と一致する。CRC32は読み込み時に1回計算する（4分のMP3で約0.1秒、4分のWAVで約0.3秒）。
- 範囲・確定範囲・分割位置は、BPM変換後の音源の長さに対する比で持つ。BPM変換は決定的なので、比で戻せば位置が一致する。
- dBの−∞はJSONで表せないため `null` で保存する。読み込み時は、すべての値をUIと同じ範囲に収める。形式・版・元の曲の照合・長さを検証し、失敗した場合は作業中の状態を変更しない。
- 読み込み後は保存前とトラックの音声バッファがビット単位で一致する。書き出しのWAVはOfflineAudioContextの処理で同じセッション内でも1 LSB揺れることがあるため、テストでは差が1 LSB以内であることを確認する。
- 自動保存はIndexedDB（DB `future-funk-lab`、ストア `autosave`）。`audio` には取り込んだ曲ファイルを変換せずにそのまま（Blob）入れ、音源が変わったときだけ書く。設定 `session` は2秒ごとに前回と比べ、違うときだけ書く。起動時は自動で復元せず、画面内のバナーで選ばせる。元音源の削除では自動保存も消す。

## 16分グリッドとスウィング（2026-10-28、#2）

- ステップは内部で常に16分音符（tick）単位で持つ。`track.steps` は64個、パターン長 `lengthTicks` は8／16／32／64（½・1・2・4小節）。グリッドは何tickごとに打てるかだけを決め、8分では偶数tickのみを使う。
- 8分→16分ではデータを変えない。16分→8分では奇数tickを消す。奇数tickがあれば画面内で確認し、パターンより後ろに隠れたtickも個数に含める。
- 発音位置は `triggerFrames()` だけで計算し、再生と書き出しで共通にする。スウィング s% のとき、グリッドの奇数番目のステップは2ステップ分の長さの s% の位置で鳴る。
- 「配置に同期」の長さはスウィングを無視したまっすぐなグリッドで計算する。「ステップ数を指定」は今までどおり8分音符単位で指定する。
- プロジェクトには `lengthTicks`・`resolution`・`swing` と、64個のtickのステップを保存する。

## トラック別の書き出し（2026-10-28、#2）

- 対象は、分割数の内側にあり、パターン内にノートがあり、ミュート／ソロで鳴っているトラック（`activeTrack()`）。ミックスと同じ判定なので、全ステムの和がミックスに一致する。除外したトラックと理由はステータスに出す。
- 各ステムは `renderPattern(snapshot, {only})` で、ミックスと同じEQ・トラック出力・マスター音量・ループ境界を通す。長さはパターン1周分。
- 複数ファイルを個別にダウンロードするとブラウザの許可が出るため、無圧縮（STORE）のZIP 1ファイルにまとめる（`zipStore()`、CRC32込み）。ファイル名はトラック番号のままで、欠番は空ける。
- 0 dBFSを超えたステムがあれば、ミックスと同じ文言で警告する。

## シーケンサーのコンパクト表示（2026-10-28、#2）

- 「コンパクト」（初期値）は1トラック1行（高さ40px）：トラック名・長さ・小さな波形、▶ M S、ステップ。トラック名で選んだ1トラックの編集部品を、シーケンサーの上の編集パネルに1つだけ出す。「詳細」は従来の表示。
- 表示の選択は `localStorage` の `ffl:view` に保存し、プロジェクトには入れない。切り替えでは再生を止めない。分割数を減らして選択中のトラックが範囲外になったらTRACK 01に戻す。
- 編集部品のHTMLは `trackEditorHtml()` で共通にする。イベントは `#sequence` からの委譲で、どちらの表示でも同じ処理が動く。`eq-value-*` などのIDは常に1か所にしか出さない。
- 既存のブラウザテストは各トラックの編集部品を直接操作するため、詳細表示で実行する。

## ドラッグ&ドロップと置き換え前の確認（2026-10-28、#9）

- ページのどこにでもファイルをドロップできる。`dataTransfer.types` に `Files` があるときだけ反応し、ドラッグ中は画面全体に案内を重ねる。扱いは選ぶ画面と同じ：曲1つは読み込み、`.json`（＋曲）はプロジェクトを開く、「元の曲を選んでください」の案内中の曲1つはその照合に使う。曲が2つ以上、`.json` が2つ以上、音声でも `.json` でもないものは理由を出して止める。処理中・録音中は受け付けない。
- 「未保存の変更」は、最後に曲を読み込んだ・プロジェクトを開いた・自動保存から復元した・保存した時点の `projectJson()` と、今の `projectJson()` が違うこと。曲を選ぶ・ドロップ・プロジェクトを開く・デモ音源・マイク録音の開始の5つの入口で、変更があれば `confirmReplace()` が画面内のバナーで確認する。`window.confirm` は使わない。「保存してから置き換える」は `saveProject()` のあとで置き換える。
- プロジェクトを開くときの確認は、`.json` を正しく読めたあと、元の曲の案内を出す前に1回だけ行う。

## スペースキーで再生/停止（2026-10-28、#9）

- `document` の `keydown` で Space を受け、チョップ後は `startSequence()`（「▶ 再生」と同じく再生中なら止める）、チョップ前で曲があれば `toggleSource()` を呼ぶ。
- 反応しないとき：フォーカスが `input`（range以外）・`select`・`textarea`・編集可能な要素にある、⌘・Ctrl・Altを押している、押しっぱなしの繰り返し（`event.repeat`）。原曲波形はフォーカス中にSpaceを自分で処理するため、既定の動作が止められた `keydown` は無視して二重に切り替えない。
- ボタンにフォーカスがあっても押さない。Chromeはボタンを `keyup` で押すため、`keydown` と `keyup` の両方で既定の動作を止める。ボタンはEnterで押せる。

## 元に戻す／やり直す（2026-10-28、#9）

- 履歴の1件は `serializeProject(projectState())`。比べるときは書き出しの設定（`export`）を除く。戻せるものと、プロジェクトに保存されるものを同じにしている。最大100件。曲を読み込む・プロジェクトを開く・自動保存から復元すると、その時点を起点に履歴を作り直す。音源の削除で空にする。
- 記録：`guarded()` を通る操作が終わったときと、`document` の `input`・`change`・`click`・`pointerup`・`keyup` の直後に、今の設定を最後の履歴と比べて違えば加える。1つの操作の中で起きた変更（イベントの直後と、非同期の処理が終わったとき）は1件にまとめる。スライダー（`input`）と波形（`canvas` 上の `pointerup`・`keyup`）は、同じ要素への変更が1秒以内に続いたら1件にまとめる。クリックと値の確定（`change`）はまとめない。まとめた結果が1つ前と同じになったら、その履歴を消す。新しい操作をしたら、やり直しの履歴は消す。
- 戻す：`restoreProject()` と共通の `assignSettings()` で設定を入れ、変わったものだけ作り直す。BPMが変わったら `rebuildSource()`、確定範囲・分割位置・分割数が変わったら `rebuildChops()`（確定範囲がなくなればチョップを消す）、それ以外はエンジンへの反映と、`trackBuildKey` が変わったトラックだけの作り直し。再生は、元の操作で止まるもの（BPM・チョップ・グリッド・ステップ数）では止まり、それ以外では鳴り続ける。書き出しの設定は今の値のまま残す。
- 入力欄にフォーカスしてから `input` が起きていれば、⌘Zはブラウザ標準の入力の取り消しに任せる。値が確定（`change`）したあとや、打っていない入力欄では、アプリの元に戻すになる。処理中は受け付けない。
